# YT-zen v3.14.0

## Update-channel health gating

The update channel (the `releases/latest/download` pair that script managers poll) is now audited
on a schedule instead of trusting that release day went well:

- A new weekly `Channel health` workflow checks out the newest published tag, rebuilds the
  artifact deterministically, and compares SHA256 against the released `yt-zen.user.js` and
  `yt-zen.meta.js`. It also asserts the released meta's `@version` matches both the tag and
  `package.json`, and probes both download URLs for HTTP 200.
- Any drift opens or updates one tracking issue labelled `channel-drift`; a healthy audit closes
  it again. The workflow holds only `contents: read` plus `issues: write`, runs in its own
  concurrency group, and never pushes commits.
- While touching CI, all workflows pin their actions by commit SHA and moved to the node24
  runtime majors (`checkout` v7, `setup-node` v7, `upload-artifact` v7), which clears the
  Node-20 deprecation warnings. `release.yml` had been the lone UTF-16-encoded file; it is now
  UTF-8 like its siblings, content unchanged apart from the action bumps.

## Engine optimizations

No behavior changed — three hot paths got cheaper:

- **Credibility Layer** caps observer-driven rescans at one per 250 ms with a leading-edge,
  timer-free gate, so YouTube's near-continuous DOM mutations no longer trigger a card sweep
  per animation frame during SPA churn.
- **Monolith Overlay Hub**'s safety-net sweep backs off to roughly one scan per four seconds
  after six consecutive empty scans; enabling a monitor or navigating still adopts immediately.
- **Discover** bounds its session seen-set on very long sessions instead of growing it without
  limit across route changes.

## New: Watch-Budget Focus Mode

A gentle daily watch budget in the zen voice — nothing is ever force-paused.

- Only visible playback on watch pages accrues time (one-second ticks through a
  registry-managed interval that pauses with the tab).
- At 80% of the budget a single toast nudges; at 100% a calm full-screen invitation offers a
  break until midnight or up to three five-minute extensions per day. Esc grants ten quiet
  minutes. Snooze and extension state persist per calendar day; browsing away always closes the
  invitation, and the next playing second brings it back if time is still spent.
- Shift+B reports remaining budget as a quiet toast, following the existing hotkey conventions
  (text-field guard, error tagging). Settings: dashboard toggle + minutes dial; usage rides on
  the engine's existing daily-rollover budget store.

## New: Shorts Policy Schedule

Time-window handling for `/shorts` beyond simple hide-or-block.

- **Block during the window** pauses Shorts inside chosen hours (work hours); **Allow only
  during the window** permits them solely inside it (wind-down). Windows use the local clock and
  may cross midnight; malformed times deactivate the gate rather than guessing.
- Blocked visits get a glass interstitial explaining the active policy, an immediate way out to
  the home feed, and a "watch anyway" session override good for thirty minutes so repeated
  clicks never nag.
- The gate re-evaluates on navigation and once a minute while parked, so a window boundary
  passing mid-scroll is honored without reloads. Independent from the existing Shorts-hiding
  switches; window math lives in a new pure `ZenResources.TimeWindow` primitive covered by unit
  tests.
