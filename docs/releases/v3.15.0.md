# YT-zen v3.15.0

## New platform primitive: `ZenResources.ScanScheduler`

Feature-level DOM rescans (badges, adoption sweeps, reconciliation) now have one shared home
instead of hand-rolled gates per feature:

- `ScanScheduler.create(scanFn, options)` returns `request()` nudges (coalesced, minimum-gap
  checked), an optional periodic tick on the shared ticker that pauses in hidden tabs, and
  idempotent `dispose()`.
- The scan function reports how much work it did. Non-zero results restore the base cadence;
  quiet scans back off exponentially toward `maxBackoffMs`, so idle pages stop paying for
  sweeps that find nothing.
- Mutation-driven nudges pass `{ priority: true }` so freshly inserted content is scanned at
  the minimum gap even while the idle tick is backed off.
- Scans never run in hidden tabs unless `runWhenHidden` is set.

The Credibility Layer is the first consumer: its 3.14.0 leading-edge gate was subsumed, and it
now also backs off while quiet, resumes from nudges only when the tab is visible, and tears the
scheduler down through the feature registry.

## Performance

- **Topic classification** compiled its keyword taxonomy into ~1,000 fresh RegExp objects per
  `classify()` call — re-run for every homepage card on every Algorithm Intelligence scan and
  every ten seconds during playback monitoring. The taxonomy now compiles exactly once per
  session, classification results cache under a title-derived key when a card has no video id,
  and behavior is unchanged.
- **Homepage feedback tokens are extracted lazily.** Recommendation scans used to serialize
  every card's Polymer data up front (~50 large `JSON.stringify` calls per scan) although only
  the handful of cards being blocked ever needs a token; extraction now happens on access,
  per item acted upon.
- **Watch-signal recording is milestone-based**: playback monitors no longer rewrite the whole
  signal blob to storage every ten seconds — a watch records when progress moves ≥5 points or
  45 seconds elapsed since the last record. Clearing signal history resets the tracker.
- **Audio analysis** reuses one frequency buffer per analyser instead of allocating per read.
- **Discover** checks watch history in small parallel batches instead of one serial IndexedDB
  round-trip per candidate, noticeably speeding topic loads.
- **SPA mount retries** (`scheduleOnReady`) use fire-and-forget timers instead of context-
  tracked ones, ending unbounded teardown-array growth across navigations.

## Fixes

- **SharedObserver no longer risks a stack overflow on YouTube's largest mutation batches**
  (`push(...mutations)` exceeded engine argument limits mid-callback; records are appended in a
  loop now).
- **SponsorBlock persistent cache cannot serve stale data as fresh.** A persisted entry whose
  one-hour in-memory freshness window had passed was re-promoted to `fresh:true` because only
  the record's 24-hour persistent TTL was compared. Freshness is now capped before comparison;
  covered by a regression unit test that fails against the old behavior.
- **SponsorBlock listener teardown registers once**, so attach/detach cycles across many
  navigations no longer accumulate duplicate cleanup entries in the feature registry.
- **Auto-dislike is its own opt-in** (`algoAutoDislikeOn`). Enabling "auto-like strongly-aligned
  watches" no longer silently sends dislike signals for unwanted-topic watches.
- **The watch optimizer pauses entirely in hidden tabs** (raw interval → shared ticker), matching
  the project-wide rule that background tabs never count or burn cycles.
- **Polymer data reads prefer the public `.data` accessor** with `__data` as a legacy fallback,
  keeping token extraction resilient to YouTube build changes.
