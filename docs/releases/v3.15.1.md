# YT-zen v3.15.1

A full-codebase audit pass: every feature registration, toggle, and shared helper was re-read
line by line. Twenty-six fixes shipped — several of them silent failures that had been in the
bundle for releases.

## Core engine

- **Thumbnail blob cache eviction never ran**: `BoundedCache.keys()` returns an Array, and the
  eviction path called `.next()` on it, throwing inside a swallowed try/catch once the cache
  passed its soft limit. Eviction works again.
- **Session resume could seek the wrong video.** The mount-wait observers behind "Resume where
  you left off" survived up to eight seconds and did not check whether the player they found
  still belonged to the recorded video; navigating during the race applied the old video's
  position (or popped its overlay) onto the new one. Both paths now verify the video id.
- The resume overlay's Escape handler was only removed by pressing Escape; dismissing via any
  button leaked one capture-phase keydown listener per show for the rest of the session.
- The oEmbed backfill's in-flight dedupe set was checked but never populated; concurrent
  passes can no longer double-fetch the same video.
- The 30-second maintenance heartbeat deserialized the entire kv store on every tick to sweep
  expired cache rows; that scan is now throttled to one pass per five minutes (pagehide
  checkpoints still run it immediately).

## Per-navigation listener stacking

The feature registry clears teardown stacks on re-apply but not on SPA navigation, and several
features re-bound listeners to the persistent `<video>` / `#movie_player` nodes inside
`onNav` callbacks — stacking one duplicate listener per navigation for the whole session.
Bound-once guards were added to: Playback Speed, Loop Video, A/B Repeat, Preferred Quality,
Always-On Captions (including the player `onStateChange` hook), Auto-Skip Ad Button, Top
Progress Bar, and End-Soon Warning.

Related fixes in the same area:

- Always-On Captions carried a redundant `cfg.changed` subscription that leaked per re-apply,
  kept applying caption CSS while the feature was disabled, duplicated a ~95-line style
  builder, and grew its stylesheet element cumulatively. Deleted — the registry's key-driven
  re-apply already covers every setting change.
- Force-Watched's `?t=` URL sync never worked (`history` was read off the videoId string);
  the screenshot toolbar poller could never exit if another path mounted the button first;
  the captions watchdog now skips its DOM probes off watch/Shorts pages; cinema mode used a
  raw timeout outside registry teardown; per-channel speed memory serializes its
  read-modify-write so rapid rate-change bursts cannot drop entries.

## Filtering, privacy & diagnostics

- **Share-URL shortener looped forever**: the rewritten href still matched the entry pattern
  and re-triggered its own observer; the guard attribute it wrote was never read.
- **Keyword Filter leaked hidden state**: the non-CSS fallback hid cards via inline style with
  no unhide pass, so disabling the feature or editing the list left cards invisible until
  YouTube happened to re-render them. Cards are now tagged and re-evaluated, and disabling
  unhides everything.
- **Country & Language Override never restored native APIs on disable** — the restore stubs
  were empty. `fetch`, `XMLHttpRequest.open/send`, `sendBeacon`, `navigator.language(s)`, and
  the Intl wrappers are now all unwrapped, with originals captured at install time.
- Adaptive Throttle measured "hidden for 60 seconds" from feature-apply time instead of from
  when the tab was actually hidden; it now tracks visibility transitions.
- Session Replay appended a record per click/navigation into an IndexedDB store nothing reads;
  it is bounded to the newest 500 records.
- Removed the dead "Auto-reload on region change" toggle (no implementing code existed), and
  the top-live-games hider's body observer now shares the common debouncer instead of running
  whole-document scans on every mutation batch.
- The Cookie Control dashboard keeps reparsing cookies after dismissal; its refresh timer now
  stops when the overlay is closed.

## Themes & element hiding

- **The hide-element presets were silently broken**: preset tables keyed entries like
  `"home-chips"` / `"home-shorts"` / `"home-thumbnails-hover"` that match no catalog id
  (the real ids are `home-chips-bar` / `home-shorts-shelf` / `home-card-hover-preview`), so
  Minimal Clean and friends never hid those elements. Keys corrected; a phantom
  `"player-topbar"` entry with no catalog counterpart was dropped.
- **Seven hide options shipped invalid CSS** (`:contains()` is not standard CSS). Their
  selectors threw on use and — because hiding joins all selections into one rule — selecting
  any of them silently disabled *every* selected hide. Those seven text-match-only entries
  were removed, and rule emission now validates each selector individually so one bad selector
  can never take out the others again.
- **Generated themes vanished on reload while staying selected**: custom themes lived only for
  the session but `themeSelected` persisted, leaving a dangling selection that applied nothing.
  Custom themes are now persisted (bounded to 50), stale selections fall back to Default, and
  theme cards highlight by stored id rather than display name (duplicate names previously
  mismatched).
- Glass Overhaul mounted even when the Theme Engine master switch was off, and its settings
  bus handler escaped feature teardown; both are gated correctly now. The icon-active-other
  palette mapping also stopped discarding its value.
